# 8. Separate a draft from an action

[Course home](../README.md) · [Curriculum](../CURRICULUM.md)

## Objective

Check the exact action and authority before changing anything.

## Explanation

Preparing text is different from sending it. Preparing a proposed record change is different from applying it. A tool may offer both, but capability is not authority. For this course, every action remains a paper proposal.

Before a real authorized action, review the exact content, destination, scope and expected effect. Check the result afterward. An uncertain result is not proof of failure; repeating a send or payment blindly could duplicate it. Follow the responsible process to inspect first.

## Worked example

Fictional review slip: draft version 2, internal status channel, one message, approved by the designated reviewer. A later request adds a customer recipient. That changes the action: the earlier slip does not authorize the new audience.

![Prepare, review the exact action, act only within authority, verify the result.](../images/action.png)

## Practice

Label each as preparation or action: write a draft; send it; list proposed record changes; apply them; explain a code snippet; execute it. What should happen if sending returns an unknown result?

## Answer and reasoning

Try the practice before reading this section.

Drafting, listing changes and explaining are preparation. Sending, applying and executing are actions. For an unknown result, inspect through the permitted process before retrying and report uncertainty. In this paper activity no message is sent, and no code is run.

## Transfer task

An approved draft changes after review to add a promised date. Can the old approval be reused automatically? No: the changed claim and action need the relevant review under the real process. Explain how version and recipient checks would expose the difference. This is our exercise rule, not a claim about every organisation's formal workflow.
